# SEO-аудит сайта LariBrand (laribrand.ru)

**Дата аудита:** 9 октября 2026
**Технология:** Next.js 15.5.19 (App Router), React 19, статическая генерация страниц услуг
**Регион продвижения:** Саратов
**Счётчик Яндекс Метрики:** 105193463

---

## 1. Первоначальное состояние

К началу работы сайт уже имел базовую SEO-подготовку: уникальные title/description на страницах,
canonical, Open Graph, карта сайта, robots.txt, схема HairSalon и Service, локальные шрифты с
`display: swap`, `next/image`, строгие security-заголовки (CSP, HSTS), noindex на юридических
страницах. Аудит выполнялся по коду проекта и по живому сайту laribrand.ru (curl).

## 3. Что уже было в порядке (не менялось)

- Уникальные title/description/keywords, canonical, OG на всех страницах — сохранены.
- Один H1 на страницу — проверено на всех 14 маршрутах.
- Self-canonical, абсолютные HTTPS-URL в sitemap, noindex-страницы (`/privacy-policy`, `/consent`, `/offer`) исключены из sitemap.
- Схема HairSalon с адресом, geo, часами работы, sameAs — расширена (@id, logo, hasMap, currenciesAccepted).
- http → https 301 работает; HSTS включён.
- Карта Яндекс — iframe с `loading="lazy"`, CSP разрешает yandex.ru.
- Мобильная адаптивность (Tailwind breakpoint'и) — изменения не затрагивали.

## 4. Оставшиеся ограничения и риски

1. **www-зеркало без 301** — нужен редирект на стороне хостинга (Vercel: домен добавляется только как apex; иначе правило редиректа). До исправления канонический тег защищает от дублей, а главное зеркало в Яндекс Вебмастере следует указать `laribrand.ru`.
2. **Счётчик загружается только после согласия на cookie** (существующее продуктовое решение). Посещения без согласия не учитываются вовсе. Юридически осторожно, но искажает данные. Альтернатива — грузить счётчик сразу, а Вебвизор включать после согласия (требует решения владельца).
3. **Формы записи нет на сайте** — запись ведётся через yclients (внешний сервис). Отправку формы (`booking_form_submit`) и подтверждённые записи отследить с сайта невозможно; доступна только воронка до клика (см. SEO_ANALYTICS.md).
4. **Lighthouse/CWV-замеры** не выполнялись (в среде нет Chromium). Косвенные метрики: First Load JS 102 kB shared, страницы услуг 125 kB; LCP-изображения с `priority`; TTFB живого сайта ~0,28 с. После деплоя снять PSI/Яндекс Вебмастер «Скорость».
5. **Частотность ключей из Wordstat** не собрана (нет авторизованного доступа к API Wordstat) — ядро в SEO_KEYWORDS.md размечено как предположительное, с приоритетами по логике спроса и текущим показам страниц.

## 5. Причины низкой глубины просмотра (1,15–1,20) — разбор без ложных выводов

Часть показателя — артефакт измерения: клиентские переходы не отправлялись в Метрику (проблема №4),
поэтому визит, начавшийся на `/` с последующим переходом на услугу, засчитывался как 1 просмотр.
После деплоя ожидать следует прежде всего **корректность данных**, а не мгновенный рост: реальную
глубину покажет Метрика через 2–4 недели. Поведенческие улучшения (FAQ, перелинковка, прозрачные
цены от) должны влиять на фактическую глубину постепенно.

Трафик страниц в отчёте Метрики — это *просмотры*, а не визиты; прямые заходы (146 просмотров/мес)
доминируют, что типично для локального салона с офлайн-каналами. Поисковые 105 просмотров/мес —
база для роста через Вебмастер и контент.
